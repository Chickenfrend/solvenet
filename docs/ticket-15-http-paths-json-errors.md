# Ticket 15: HTTP paths and JSON errors

## Behavior

- Coordinator routing parses request targets with `urllib.parse.urlsplit`, so
  query strings do not become part of run or assignment identifiers.
- Path segments are strictly percent-decoded as UTF-8. Invalid escapes return
  JSON 400 errors; empty, extra, encoded-slash, and invalid identifier segments
  do not match routes and return JSON 404 errors.
- Run and assignment routes accept the coordinator's 32-character lowercase
  hexadecimal identifiers. Percent-encoded characters are accepted when they
  decode to a valid identifier.
- Every coordinator-generated error uses `{"error":"..."}` with
  `Content-Type: application/json`, including errors generated by the stdlib
  request handler.
- Unsupported methods, including `PUT`, `DELETE`, and `PATCH`, return 405 and
  `Allow: GET, HEAD, POST`.
- `HEAD` follows GET routing and status behavior but sends no response body.
- Missing, malformed, empty, oversized, and invalid JSON request bodies receive
  explicit 411, 400, or 413 JSON responses as appropriate.

## Files changed

- `coordinator/src/solvenet/server.py` — normalized path parsing, identifier
  validation, JSON body parsing, JSON stdlib errors, method handling, and HEAD
  behavior.
- `coordinator/tests/test_coordinator.py` — API coverage for queries, percent
  encoding, malformed run and assignment paths, unsupported methods, malformed
  JSON and `Content-Length`, content types, and HEAD responses.
- `protocol/v1.md` — documented routing, path validation, error statuses and
  envelopes, allowed methods, and HEAD semantics.

installed in the environment; unittest is the repository's documented command.

## Remaining concerns

- The coordinator remains a loopback-only stdlib HTTP prototype without
  authentication.
- Request bodies are read according to `Content-Length`; chunked request bodies
  are not supported.
- Identifier syntax is currently coupled to the UUID-hex identifiers generated
  by the store. A future identifier format will require updating route validation
  and the protocol documentation together.
