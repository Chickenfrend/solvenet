# SolveNet local worker protocol v1

HTTP JSON, UTF-8. This prototype listens on loopback and has no authentication.
Run one coordinator process per database. Do not expose its API publicly.
Requests are limited to 256 KiB. Errors are `{ "error": "description" }`.
The coordinator owns a single pinned Lean environment; workers do not select it.

## Submit and inspect a run

`POST /v1/runs`:

```json
{"statement":"(n : Nat) : n + 0 = n","imports":["Init"],"attempts":3,"model":"scripted","max_output_tokens":2048}
```

Returns 201 with `problem_id` and `run_id`. Defaults are shown except for the
required statement. `attempts` is 1–100; `max_output_tokens` is 1–32768.
This creates independent jobs immediately, each with at most three assignments.
Thus a run has a bounded number of dispatches (at most `attempts * 3`). This is
not yet monetary or actual token accounting. The scripted executor emits a fixed
fixture; a future real provider must enforce the requested generation limit.

`GET /v1/runs/{id}` returns the problem, jobs, assignments, attempts and verification
outcomes. Lease tokens are never included. Run states: `running`, `solved`,
`exhausted`, `error`. A verifier infrastructure failure sets `error`; queued jobs
stop. Success sets `solved` and cancels queued jobs. Already dispatched jobs may
finish and their outputs are retained and verified.

`GET /health` returns `{"status":"ok"}` (HTTP liveness, not verifier readiness).

## Claim work

`POST /v1/claim`:

```json
{"worker_id":"homelab-1","models":["scripted"]}
```

Returns 204 if no compatible job exists, otherwise 200:

```json
{
  "protocol_version": 1,
  "assignment_id": "opaque-id",
  "lease_token": "opaque-secret",
  "lease_expires_at": 1790000030.0,
  "heartbeat_seconds": 10.0,
  "job": {
    "id": "opaque-job-id",
    "kind": "model.generate",
    "model": "scripted",
    "statement": "(n : Nat) : n + 0 = n",
    "imports": ["Init"],
    "messages": [
      {"role":"system","content":"Return only a Lean tactic proof body."},
      {"role":"user","content":"(n : Nat) : n + 0 = n"}
    ],
    "max_output_tokens": 2048,
    "timeout_seconds": 120
  }
}
```

Times are Unix seconds. The worker uses `heartbeat_seconds` for renewal rather
than relying on synchronized clocks. Worker capabilities are claims, not trusted
attestations. A worker advertises one free slot by making one claim.

## Renew and submit

`POST /v1/assignments/{id}/heartbeat`:

```json
{"lease_token":"opaque-secret"}
```

Returns 200 with `lease_expires_at`. Expired/invalid assignments return 409.

`POST /v1/assignments/{id}/result`:

```json
{"lease_token":"opaque-secret","status":"completed","output":{"text":"rfl"},"usage":{"input_tokens":null,"output_tokens":null}}
```

Output must be a nonempty proof body, at most 128 KiB. Unknown usage is omitted or
null, never assumed to be zero. A provider/executor failure instead submits:

```json
{"lease_token":"opaque-secret","status":"failed","error":"Provider unavailable"}
```

Returns 200 `{"accepted":true}`. This acknowledges storage, not proof validity.
Repeated semantically identical JSON is acknowledged without another attempt.
A changed terminal result, invalid token, or late submission returns 409.
An acknowledged result can be retried after lease expiry and coordinator restart.

Abandoned and explicitly failed assignments count toward the three-assignment
limit. Expired work can be reassigned; late outputs are rejected, so lost work and
unknown usage are visible as expired assignments. Invalid proofs are completed
attempts, not execution failures, and are not automatically retried.
